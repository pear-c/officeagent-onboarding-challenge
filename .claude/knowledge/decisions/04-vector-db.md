# Decision 04. 벡터 DB — Chroma

> **결정**: Chroma (Docker 서버 모드)
> **핵심 근거**: 이 과제 규모(청크 50~500개)에서 벡터 DB 간 성능 차이 무의미. 셋업 단순성으로 선택.

## 후보 비교

| 항목 | Chroma ⭐ | Qdrant | pgvector |
|---|---|---|---|
| 검색 속도 (50~500 벡터) | <1ms | <1ms | <1ms |
| Docker 셋업 | 1줄 | 1줄 | 3줄 (확장 설치) |
| Python 클라이언트 코드량 | ~10줄 | ~15줄 | ~30줄 (SQLAlchemy) |
| 임베디드 모드 | ✅ | 실험적 | ❌ |
| 메타데이터 필터 | 기본 | 고급 (강력) | SQL WHERE (강력) |
| ACID 트랜잭션 | ❌ | ❌ | ✅ |
| Docker 이미지 크기 | ~150MB | ~80MB | ~400MB |

## 선택 근거

1. **이 규모에서 성능 차이 0** — 세 DB 모두 <1ms. 성능으로 선택할 이유 없음
2. **셋업 단순** — `docker run chromadb/chroma` 한 줄. 채점자 환경에서도 동일
3. **임베디드 모드** — 시드 스크립트에서 Docker 없이 데이터 투입 가능
4. **컬렉션 단위 관리** — 캐시 무효화(삭제+재생성)가 직관적

## 탈락 사유

- **Qdrant**: 성능 우수하나 이 규모에서 차이 없음. 추가 이점 불충분
- **pgvector**: 관계형 데이터 통합/ACID가 장점이나 이 과제에 불필요. SQLAlchemy 코드량 부담

## 대규모 확장 시

문서 100만 건 이상으로 확장 시 Qdrant 또는 pgvector 전환 고려 필요. 현재 `chroma_store.py`를 `VectorStore` 인터페이스로 감싸두면 전환 비용 최소화 가능.
