# Decision 06. 청킹 전략 — 하이브리드 (재귀 분할 + 마크다운 인식)

> **결정**: 파일 포맷별 분기. `.md` → 마크다운 인식, `.txt/.pdf` → 재귀 분할
> **핵심 근거**: PRD "어떤 문서의 어떤 부분에서 왔는지 출처" → 마크다운 헤더 기반이 가장 정확

## 전략별 특성

| 항목 | 고정 크기 | 재귀 분할 | 마크다운 인식 | 시맨틱 청킹 |
|---|---|---|---|---|
| 구현 복잡도 | ~20줄 | ~50줄 | ~60줄 | ~100줄+ |
| 출처 추적 정확도 | 낮음 | 중~높음 | **높음** | 높음 |
| 맥락 보존 | 낮음 | 높음 | **매우 높음** (구조화 문서) | 매우 높음 |
| LLM 추가 호출 | 없음 | 없음 | 없음 | **있음** |
| 포맷 범용성 | 높음 | 높음 | .md에 최적 | 높음 |

> 위 Retrieval Hit Rate 수치는 평가 하네스 자체 측정으로 채울 예정.

## PRD 요구사항 분석

| PRD 요구사항 | 필요한 청킹 특성 | 최적 전략 |
|---|---|---|
| "어떤 문서의 **어떤 부분**에서 왔는지 출처" | 출처 추적 정확도 | 마크다운 인식 > 재귀 > 고정 |
| "환각 없이 적절히 처리" | 맥락 보존 (불완전 청크→환각 유발) | 마크다운 인식 ≈ 재귀 >> 고정 |
| "최소 2개 포맷 지원" | 포맷 범용성 | 재귀 > 고정 >> 마크다운 |

→ **단일 전략으로는 모든 요구사항을 만족 못 함** → 하이브리드

## 하이브리드 설계

```python
def chunk_document(text: str, filename: str, chunk_size=400, overlap=80):
    if filename.endswith('.md'):
        return markdown_aware_chunk(text, chunk_size, overlap)
    else:
        return recursive_chunk(text, chunk_size, overlap)
```

### 재귀 분할 (.txt, .pdf)

구분자 우선순위: `\n\n` → `\n` → `. ` → ` `

1. 최우선 구분자로 분할
2. 각 조각이 chunk_size 초과 시 → 다음 우선순위 구분자로 재분할
3. overlap만큼 인접 청크 겹침

### 마크다운 인식 (.md)

1. `##` 이상의 헤더를 기준으로 섹션 분할
2. 각 청크에 **헤더 경로 메타데이터** 태깅 (예: "코드 리뷰 정책 > 리뷰 체크리스트")
3. 섹션이 chunk_size 초과 시 → 재귀 분할로 fallback
4. 출처 형식: `{파일명} > {섹션 헤더}`

## 파라미터

| 파라미터 | 값 | 근거 |
|---|---|---|
| chunk_size | 400자 | 한국어 평균 문장 50~80자 × 5~8문장 = 적정 맥락 단위 |
| overlap | 80자 (20%) | 청크 경계에 걸친 정보 보존 |

## 탈락 사유

- **고정 크기**: 문장 중간에서 잘림 → 출처 추적 불가 + 환각 유발
- **시맨틱 청킹**: 품질 최고이나 모든 문장 임베딩 필요 → 처리 시간 100배↑, 8일 기한 부담
