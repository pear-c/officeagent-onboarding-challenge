# 작업 파이프라인 실행

전체 6단계 파이프라인을 빠짐없이 실행한다. 인자로 작업 설명을 받는다.

**사용법**: `/pipeline <작업 설명>` 또는 `/pipeline` (이전 작업 이어서)

---

## 파이프라인 단계

### 1단계: 지시 확인 + 맥락 복원

1. 인자가 있으면 해당 작업을 새로 시작한다.
2. 인자가 없으면 `.claude/tasks/` 하위에서 진행 중인(🟡) CHECKLIST.md를 찾아 이어서 진행한다.
3. 기존 작업이면 PLAN.md, CONTEXT.md, CHECKLIST.md를 읽어 맥락을 복원한다.
4. `.claude/tasks/NEXT_TASKS.md`를 참고하여 작업 후보와의 관계를 확인한다.

**사용자에게 보고**: 작업 내용을 간략히 정리하고 진행 여부를 확인받는다.

---

### 2단계: 계획 수립 (planner 에이전트)

**조건**: 새 작업일 때만 실행. 이어서 하는 작업은 건너뛴다.

1. `planner` 에이전트를 실행하여 작업 분석 + 계획 초안 작성
2. 사용자에게 계획 초안을 제시하고 피드백 수렴
3. 승인 후 `.claude/tasks/{task-name}/` 에 3가지 문서 저장:
   - `PLAN.md` (설계도)
   - `CONTEXT.md` (시방서)
   - `CHECKLIST.md` (공정표)

**UI 작업 포함 시**: `ui-ux-designer` 에이전트를 추가 실행하여 화면 명세 작성

**사용자에게 보고**: "계획 수립 완료. 구현을 시작합니다." 또는 수정 요청 대기

---

### 3단계: 구현 (coder 에이전트)

1. `coder` 에이전트를 실행하여 PLAN.md 순서대로 코드 작성
2. 스킬 훅(`skill-suggester.py`)이 자동으로 관련 스킬을 제안 → 반드시 참고
3. CHECKLIST.md를 실시간 업데이트 (완료 항목 `[x]` 체크)
4. CLAUDE.md 코딩 규칙 준수:
   - 불변성, 함수 50줄 이하, 파일 800줄 이하, 중첩 4레벨 이하
   - 에러 처리 명시적, 하드코딩 금지, 입력 검증

**참고**: `post-work-checker.py` 훅이 매 Write/Edit마다 `.claude/change-log.jsonl`에 자동 기록

---

### 4단계: 변경 기록 확인

구현이 완료되면:

1. `.claude/change-log.jsonl`을 읽어 이번 작업에서 변경된 파일 목록을 수집한다
2. 변경 파일이 없으면 "변경 사항 없음"으로 보고하고 파이프라인을 종료한다
3. 변경된 파일의 확장자별 분류를 정리한다

**사용자에게 보고**: 변경된 파일 수와 확장자 요약

---

### 5단계: 검증 (verifier 에이전트)

**이 단계는 절대 생략하지 않는다.**

1. `verifier` 에이전트를 실행한다
2. verifier가 수행하는 작업:
   - 변경 로그 기반 확장자별 검증 명령어 실행
     - `.java` → `./gradlew compileJava`
     - `.ts/.tsx` → `npx tsc --noEmit`
     - `.py` → `python -m py_compile`
   - 보안 패턴 검사 (시크릿 하드코딩, SQL 인젝션 등)
3. 오류 대응:
   - **0개**: 다음 단계로 진행
   - **1~3개**: verifier가 직접 수정 → 수정 후 재검증
   - **4개 이상**: 사용자에게 보고 + 전문 에이전트 추천

**사용자에게 보고**: 검증 결과 요약 (오류 수, 보안 경고 수)

---

### 6단계: 리뷰 (reviewer 에이전트)

**이 단계는 절대 생략하지 않는다.**

1. `reviewer` 에이전트를 실행한다
2. reviewer가 수행하는 5가지 관점 리뷰:
   - 설계 리뷰 (PLAN.md 반영 여부)
   - 코드 품질 리뷰 (CLAUDE.md 규칙 준수)
   - 보안 리뷰 (입력 검증, 시크릿, SQL 인젝션)
   - 성능 리뷰 (N+1, 인덱스, 페이지네이션)
   - 테스트 리뷰 (커버리지, 엣지 케이스)
3. 리뷰 결과 심각도 분류:
   - **HIGH**: 즉시 수정 (coder 에이전트 재실행 또는 직접 수정)
   - **MEDIUM**: 사용자와 협의 후 수정
   - **LOW**: 기록만 남기고 다음 작업에서 개선

**HIGH 이슈 수정 시**: 수정 후 5단계(verifier)부터 다시 실행한다.

---

## 완료 처리

모든 단계가 끝나면:

1. CHECKLIST.md를 최종 업데이트 (검증/리뷰 항목 체크)
2. CONTEXT.md에 최종 변경 파일 목록 추가
3. 사용자에게 최종 보고:

```
[파이프라인 완료]
- 작업: {작업명}
- 변경 파일: N개
- 검증: 통과 / 오류 N개 수정
- 리뷰: HIGH N개 / MEDIUM N개 / LOW N개
- 빌드: SUCCESS / FAIL

다음 작업 후보: .claude/tasks/NEXT_TASKS.md 참조
```

---

## 규칙

- **5단계(verifier)와 6단계(reviewer)는 어떤 상황에서도 생략하지 않는다**
- HIGH 리뷰 이슈 발견 시 반드시 수정하고 verifier를 재실행한다
- 각 단계 완료 시 사용자에게 간략히 보고한다
- 에이전트 실행은 독립적인 경우 병렬로, 의존적인 경우 순차로 실행한다
- 작업 중단 시 CHECKLIST.md에 현재 진행 상태를 반드시 저장한다
