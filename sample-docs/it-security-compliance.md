## 2. 접근 제어

### 2.1 인증 정책

#### 비밀번호 규칙
- 최소 길이: 14자 (관리자 계정은 20자)
- 구성: 대문자 + 소문자 + 숫자 + 특수문자 각 1개 이상
- 변경 주기: 90일 (관리자 계정은 30일)
- 이력 제한: 최근 12개 비밀번호 재사용 금지
- 잠금: 5회 실패 시 30분 잠금, 10회 연속 실패 시 영구 잠금 (보안팀 해제)

#### 다중 인증 (MFA) 요건

| 시스템 | MFA 필수 | 방식 | 비고 |
|--------|---------|------|------|
| VPN | O | TOTP + 인증서 | 외부 접속 시 필수 |
| 프로덕션 서버 | O | 하드웨어 키 (YubiKey) | SSH 접속 금지, kubectl만 허용 |
| 클라우드 콘솔 (AWS) | O | TOTP | root 계정은 하드웨어 키 |
| 사내 메일 | O | TOTP | 외부 네트워크 접속 시 |
| 개발 서버 | X | - | 사내 네트워크 한정 |
| 사내 위키 | X | - | 읽기 전용은 MFA 불필요 |

### 2.2 권한 관리

#### RBAC (역할 기반 접근 제어)
- **Super Admin**: 인프라팀장 + CISO만 보유. 전 시스템 접근 가능
- **Service Admin**: 서비스별 담당자 1명. 해당 서비스 설정 변경 가능
- **Developer**: 개발서버 접근 + 스테이징 배포 권한
- **Viewer**: 대시보드 읽기 전용

#### 권한 검토 주기
- Super Admin: 월 1회 (CISO 직접 검토)
- Service Admin: 분기 1회
- Developer/Viewer: 반기 1회
- 퇴사자: 당일 즉시 전 권한 회수 (인사팀 → 보안팀 자동 연동, SLA 1시간)

### 2.3 특수 접근

#### 프로덕션 DB 접근
- 일반 개발자: 금지
- DBA: Bastion 호스트 경유 + MFA + 쿼리 감사 로그 자동 기록
- 긴급 접근 (장애 시): "Break Glass" 절차 적용
  1. 접근 요청 (Jira 티켓 자동 생성)
  2. 당직 관리자 구두 승인 (전화 녹음)
  3. 최대 2시간 접근 권한 부여
  4. 작업 완료 즉시 권한 자동 회수
  5. 48시간 이내 사후 보고서 제출 (CISO 검토)

## 3. 개인정보 보호

### 3.1 수집 원칙
- 목적 명시: 수집 시 구체적 이용 목적 고지 필수
- 최소 수집: 서비스 제공에 필수적인 항목만 수집
- 동의: 개인정보 수집 전 명시적 동의 획득 (옵트인)
- 파기: 목적 달성 또는 보유 기간 만료 시 지체 없이 파기

### 3.2 개인정보 영향평가 (PIA)

| 대상 | 평가 시기 | 수행 주체 | 승인 |
|------|----------|----------|------|
| 신규 서비스 (개인정보 처리) | 서비스 런칭 전 | 개발팀 + 법무팀 | DPO |
| 기존 서비스 변경 (DB 스키마 변경) | 변경 배포 전 | 개발팀 | 보안팀 |
| 외부 업체 데이터 공유 | 계약 체결 전 | 법무팀 | DPO + 대표이사 |
| 해외 데이터 이전 | 이전 실행 전 | 법무팀 + 보안팀 | DPO + CISO |

### 3.3 데이터 주체 권리 처리

- 열람 요청: 접수 후 10일 이내 응답
- 정정 요청: 접수 후 10일 이내 처리
- 삭제 요청: 접수 후 10일 이내 파기 (법적 보관 의무 항목 제외)
- 처리 정지: 접수 후 10일 이내 정지 조치
- DPO 연락처: privacy@company.com, 내선 5678

### 3.4 개인정보 유출 대응

1. 유출 인지 → 즉시 보안팀 + DPO 통보
2. 유출 범위 파악 (4시간 이내)
3. 피해 최소화 조치 (접근 차단, 비밀번호 초기화 등)
4. 개인정보보호위원회 신고: 인지 후 72시간 이내
5. 정보주체 통지: 인지 후 72시간 이내
6. 원인 분석 + 재발 방지: 30일 이내 보고서

## 4. 인시던트 대응

### 4.1 심각도 분류

| 등급 | 정의 | 사례 | 초기 대응 | 경영진 보고 |
|------|------|------|----------|-----------|
| P1 (Critical) | 서비스 전면 중단 또는 데이터 유출 | 랜섬웨어 감염, 고객 DB 유출 | 즉시 (15분) | 즉시 |
| P2 (High) | 핵심 기능 장애 | 결제 시스템 오류, 인증 서버 다운 | 30분 이내 | 1시간 이내 |
| P3 (Medium) | 비핵심 기능 장애 | 알림 발송 지연, 검색 속도 저하 | 2시간 이내 | 익일 |
| P4 (Low) | 사소한 이슈 | 오탈자, UI 깨짐, 로그 경고 | 24시간 이내 | 주간 보고 |

### 4.2 에스컬레이션 체계

```
P1: 담당 엔지니어 → 팀장 (15분) → CTO (30분) → CEO (1시간)
P2: 담당 엔지니어 → 팀장 (30분) → CTO (2시간)
P3: 담당 엔지니어 → 팀장 (2시간)
P4: 담당 엔지니어 (자체 처리)
```

### 4.3 사후 분석 (Post-mortem)

- P1/P2 인시던트: 해결 후 5영업일 이내 사후 분석 보고서 필수
- 보고서 포함 사항: 타임라인, 근본 원인(Root Cause), 영향 범위, 재발 방지 대책
- 비난 금지 원칙: 사후 분석에서 개인을 비난하지 않음 (시스템 개선에 집중)
- 재발 방지 대책의 이행 기한: P1은 30일, P2는 60일 이내
- 이행 확인: 보안팀이 기한 내 이행 여부 추적

## 5. 네트워크 보안

### 5.1 네트워크 분리

| 영역 | 접근 가능 대상 | 방화벽 규칙 |
|------|-------------|-----------|
| DMZ | 외부 트래픽 → 로드밸런서 | 80, 443만 허용 |
| 서비스 영역 | 로드밸런서 → 앱 서버 | 서비스 포트만 허용 |
| 데이터 영역 | 앱 서버 → DB | DB 포트만 허용, IP 화이트리스트 |
| 관리 영역 | VPN → Bastion → 서버 | SSH(22) Bastion만 허용 |

### 5.2 외부 접속

- 재택근무 시 VPN 필수 (WireGuard, 사내 인증서 + TOTP)
- 공용 Wi-Fi에서 VPN 없이 사내 시스템 접속 금지
- 해외 출장 시: 보안팀에 사전 신고 + 전용 VPN 프로파일 발급
- 개인 기기(BYOD): MDM 설치 필수, 미설치 기기는 사내 네트워크 접속 불가

### 5.3 로그 관리

- 모든 시스템 접근 로그: 최소 1년 보관
- 인증 실패 로그: 실시간 모니터링 + 알림
- 개인정보 접근 로그: 3년 보관 (법적 요건)
- 로그 형식: 구조화 로그 (JSON) 필수

```json
{
  "timestamp": "2026-01-15T09:30:00+09:00",
  "level": "WARN",
  "service": "user-service",
  "action": "LOGIN_FAILED",
  "user_id": "masked_uid_***",
  "ip": "10.0.1.xxx",
  "reason": "INVALID_PASSWORD",
  "attempt": 3
}
```

## 6. 소프트웨어 보안

### 6.1 개발 보안 (Secure SDLC)

| 단계 | 활동 | 도구 | 담당 |
|------|------|------|------|
| 설계 | 위협 모델링 (STRIDE) | Microsoft TMT | 개발팀 + 보안팀 |
| 코딩 | 정적 분석 (SAST) | SonarQube + Semgrep | CI 자동화 |
| 빌드 | 의존성 취약점 스캔 | Trivy + Snyk | CI 자동화 |
| 테스트 | 동적 분석 (DAST) | OWASP ZAP | 보안팀 (월 1회) |
| 배포 | 컨테이너 이미지 스캔 | Trivy | CD 자동화 |
| 운영 | 침투 테스트 | 외부 업체 | 보안팀 (연 1회) |

### 6.2 오픈소스 관리

- 신규 라이브러리 도입 시 법무팀 라이선스 검토 필수 (GPL, AGPL 주의)
- CVSS 7.0 이상 취약점: 발견 후 7일 이내 패치
- CVSS 9.0 이상 취약점: 발견 후 24시간 이내 패치 (긴급 배포)
- 의존성 업데이트: 최소 월 1회 Dependabot PR 검토

### 6.3 시크릿 관리

- 소스 코드에 시크릿 하드코딩 절대 금지
- 시크릿 저장소: AWS Secrets Manager + External Secrets Operator
- 시크릿 교체 주기: API 키 90일, DB 비밀번호 30일, 인증서 1년
- pre-commit 훅으로 시크릿 탐지 (gitleaks) 적용 필수
- 유출 발견 시: 즉시 교체 + 보안팀 보고 + 접근 로그 분석

## 7. 컴플라이언스

### 7.1 적용 법규

| 법규 | 적용 범위 | 담당 부서 | 감사 주기 |
|------|----------|----------|----------|
| 개인정보보호법 | 전사 | 법무팀 + DPO | 연 1회 |
| 정보통신망법 | 온라인 서비스 | 보안팀 | 연 1회 |
| 전자금융거래법 | 결제 서비스 | 보안팀 + 재무팀 | 연 1회 |
| ISMS-P | 정보보호 관리체계 | 보안팀 | 연 1회 인증심사 |
| PCI DSS | 카드결제 처리 | 보안팀 | 연 1회 (QSA 심사) |

### 7.2 내부 감사

- 정기 감사: 연 2회 (상반기 6월, 하반기 12월)
- 특별 감사: 보안 사고 발생 시 또는 경영진 요청 시
- 감사 범위: 접근 권한, 로그 관리, 개인정보 처리, 시크릿 관리
- 감사 결과 보고: 감사 완료 후 10영업일 이내 경영진 보고
- 개선 권고 이행: 60일 이내 이행 + 보안팀 확인

### 7.3 교육

- 전 임직원: 정보보안 교육 연 2회 (상/하반기), 이수율 100% 필수
- 개발자: Secure Coding 교육 연 1회 추가
- 관리자 (Admin 권한 보유자): 권한 관리 교육 분기 1회
- 신규 입사자: 입사 후 1주 이내 보안 교육 필수 이수
- 미이수 시: 사내 시스템 접근 차단 (교육 이수 후 해제)
