Part 6 · Retrospective

직접 구현 vs LangChain

과제 제출 후 LangChain으로 옮겨보며 느낀 것
직접 구현 — 이번 과제
From Scratch
+ 각 단계의 의사결정이 명확 — 청킹·임베딩·검색·캐시·거절까지 손으로 통제
+ 트러블슈팅 깊이 — 좀비 캐시·동의어 우회 같은 엣지 케이스를 직접 만나봄
− 보일러플레이트 — Provider 추상화·캐시 키 관리 등 코드량이 많음
LangChain — 제출 후
Framework
+ 빠른 프로토타이핑 — RetrievalQA 한 줄로 RAG 동작
+ 생태계 — Hybrid retriever, 다양한 vectorstore가 이미 추상화됨
− 추상화 비용 — 디버깅 시 내부 동작 파악 어려움
− 세밀한 제어 약함 — 거절 패턴 매칭 같은 커스텀 로직 끼워넣기 번거로움
느낀 점
01 · 선택 기준
PoC = 직접, 프로덕션 = 평가 후 선택. 추상화는 도메인 요구가 단순할 때 유리.
02 · 안목
직접 짜본 경험이 LangChain 코드를 더 잘 읽게 해줌. 추상화의 비용/이득 판단 가능.
03 · 현재 갭
검색 전략(Hybrid)이 Chroma 한계로 막혔을 때 — LangChain의 다중 retriever는 매력적.
Key Takeaway
프레임워크는 답이 아니라 도구 — 직접 짜본 경험이 도구를 고를 안목을 만든다
